# สคริปต์นำเสนอสไลด์โครงงาน (5 นาที) & สรุปเนื้อหา 9 สไลด์

> **ชื่อโครงงาน:** การจัดการข้อมูลรหัสยามาตรฐานไทย (TMT) เพื่อพัฒนาระบบสืบค้น แปลงรหัส และบูรณาการข้อมูลยาโรงพยาบาลสมเด็จพระยุพราชสายบุรี  
> **ผู้นำเสนอ:** ทีมเภสัชกรรมสารสนเทศ (Little-Ong Rx)  
> **เวลาที่ใช้:** นำเสนอ 5 นาที / ถาม-ตอบ 2 นาที  
> **ไฟล์สไลด์ฉบับเต็ม:** เปิดดูและพิมพ์เป็น PDF ได้ที่ `project_submission/presentation_slides.html`

## ⏱️ ไทม์ไลน์การพูดนำเสนอ 5 นาที (Presentation Timing Script)

### [นาทีที่ 0:00 - 0:30] สไลด์ที่ 1: หน้าปกโครงงาน
* **ข้อความบรรยาย:**
  > "กราบเรียนอาจารย์และสวัสดีเพื่อนๆ ทุกคนครับ วันนี้กลุ่มกระผมขอเสนอนำเสนอโครงงานในหัวข้อ **'การจัดการข้อมูลรหัสยามาตรฐานไทย (TMT) เพื่อพัฒนาระบบสืบค้น แปลงรหัส และบูรณาการข้อมูลยาโรงพยาบาลสมเด็จพระยุพราชสายบุรี'** ซึ่งครอบคลุมกระบวนการตั้งแต่ Data Cleansing, Relational Database, Apache Airflow ETL ไปจนถึง Agentic AI Pipeline Automation ครับ"

---

### [นาทีที่ 0:30 - 1:15] สไลด์ที่ 2: ปัญหาและที่มาของข้อมูล (เกณฑ์ 4.1, 4.2)
* **ข้อความบรรยาย:**
  > "ที่มาของข้อมูล เราใช้ข้อมูลจริงขนาดใหญ่จาก **สำนักพัฒนามาตรฐานระบบข้อมูลสุขภาพไทย (สมสท.)** เวอร์ชันล่าสุด ประกอบด้วย **112,069 Concepts** และสายสัมพันธ์ **111,953 Relations** ซึ่งเกินกว่าเกณฑ์ 1,000 แถวอย่างมาก
  > ปัญหาหลักในโรงพยาบาลคือ รหัสยาในระบบ HIS ไม่ตรงกับรหัสเบิกจ่าย สปสช. และการแปลงรหัสย้อนกลับไปหารหัสสากล WHO-ATC ทำได้ยากและล่าช้ามากครับ"

---

### [นาทีที่ 1:15 - 2:00] สไลด์ที่ 3: เทคนิค Data Cleansing 1 & 2 (เกณฑ์ 1.1, 1.2)
* **ข้อความบรรยาย:**
  > "ในส่วนของ Data Cleansing เราใช้ 2 เทคนิคหลัก:
  > **เทคนิคที่ 1:** ทำ Unicode Normalization (NFKD) และ Regex เพื่อจัดการสระภาษาไทยลอย ลบ Control Characters และแปลงหน่วยความแรงยา (mg, g, mL) ให้เป็นมาตรฐานเดียวกัน
  > **เทคนิคที่ 2:** ตรวจสอบ Referential Integrity และ Key Deduplication โดยเราได้ตรวจจับและตัดความสัมพันธ์ที่เป็น Self-loop และ Orphan Relations ที่ไม่มีตัวตนจริงในตาราง Concept เพื่อป้องกันความผิดพลาดในระบบฐานข้อมูลครับ"

---

### [นาทีที่ 2:00 - 2:45] สไลด์ที่ 4: Data Integration & Graph Transformation (เกณฑ์ 1.3)
* **ข้อความบรรยาย:**
  > "**เทคนิคที่ 3 Data Integration:** เราบูรณาการ 3 แหล่งข้อมูลข้ามระบบ คือ Master TMT, รหัสสากล WHO-ATC และ แคตตาล็อกยา รพ.สายบุรี
  > และทำ Data Transformation โดยสร้างลำดับขั้น Hierarchy Level 1 ถึง 6 (จากสารสำคัญ SUBS ไปจนถึง บรรจุภัณฑ์ TPP) ทำให้ระบบสามารถจับคู่ยาโรงพยาบาลและสกัดรหัส ATC ออกมาได้ด้วยความแม่นยำสูงกว่า 90% ครับ"

---

### [นาทีที่ 2:45 - 3:30] สไลด์ที่ 5: Database & Warehouse Management (เกณฑ์ 2.1, 2.2, 2.3)
* **ข้อความบรรยาย:**
  > "ในส่วนฐานข้อมูล เราเลือกใช้ **Relational Database** เนื่องจากข้อมูลยามีลำดับขั้น Parent-Child ที่ต้องรักษาความถูกต้องเชิงสัมพันธ์ (Referential Integrity) ผ่าน Foreign Key อย่างเคร่งครัด และต้องการคุณสมบัติ ACID เพื่อความปลอดภัยในการจ่ายยาผู้ป่วย
  > เราออกแบบ 4 ตารางตามมาตรฐาน 3NF พร้อมสร้าง B-Tree Indexing และเขียน Python Code สำหรับ Query ข้อมูล 3 รูปแบบ ทั้งการสืบค้นสายสัมพันธ์ระดับยา, การสรุปสถิติ และการผสานข้อมูลกับระบบ HIS ครับ"

---

### [นาทีที่ 3:30 - 4:15] สไลด์ที่ 6: Apache Airflow ETL DAG (เกณฑ์ 3.1, 3.2)
* **ข้อความบรรยาย:**
  > "กระบวนการ ETL เราออกแบบ DAG ใน Apache Airflow เป็น 5 ขั้นตอนต่อเนื่อง: สกัดไฟล์ XLS -> ทำ Cleansing -> บูรณาการ ATC -> โหลดเข้า Database -> และส่งต่อให้ Agentic AI ตรวจสอบ
  > โดยเราตั้ง Schedule เป็น `0 2 1 * *` รันอัตโนมัติทุกวันที่ 1 ของเดือน เวลาตีสอง เพื่อให้สอดรับกับรอบการปล่อยไฟล์ Master Release ประจำเดือนของ สมสท. ครับ"

---

### [นาทีที่ 4:15 - 4:45] สไลด์ที่ 7: Agentic AI & n8n Automation (เกณฑ์ 3.3)
* **ข้อความบรรยาย:**
  > "ไฮไลท์สำคัญในส่วนคะแนน 10 คะแนนนี้ คือการใช้ **Agentic AI** เข้ามาเป็นผู้กำกับดูแล Pipeline (Supervisor) โดย Agent จะตรวจสอบ Data Health, สัดส่วน Orphan Ratio, และหากพบยาเข้าใหม่ที่ยังไม่แมป Agent จะเรียก Fuzzy Tool มาช่วยจับคู่ให้อัตโนมัติ จากนั้นส่งผลผ่าน Webhook เข้า **n8n** เพื่อแจ้งเตือนสรุปผลเข้า Slack และแจ้งเตือนด่วนเข้า LINE Notify ของทีมเภสัชกรทันทีครับ"

---

## 🎯 แนวทางการตอบคำถามช่วงถาม-ตอบ (Q&A 2 นาที)

1. **ถาม: ทำไมถึงไม่เลือกใช้ NoSQL เช่น MongoDB หรือ Neo4j?**
   * **ตอบ:** "เนื่องจากข้อมูลยาในระบบสารสนเทศโรงพยาบาล (HIS) ต้องทำงานร่วมกับตารางเวชระเบียนผู้ป่วยและการสั่งจ่ายยาที่มีมาตรฐานความปลอดภัยระดับ ACID สูง และการใช้ Relational Database ที่มี Foreign Key และ B-Tree Index บนตารางความสัมพันธ์ สามารถตอบสนองการสืบค้นความสัมพันธ์แบบ Directed Graph ได้ในเวลาต่ำกว่า 1 มิลลิวินาที โดยไม่เพิ่มความซับซ้อนของโครงสร้างพื้นฐานระบบครับ"

2. **ถาม: Agentic AI แตกต่างจากการเขียน Script แจ้งเตือนธรรมดาอย่างไร?**
   * **ตอบ:** "Script ธรรมดาจะทำได้แค่ส่งแจ้งเตือนตามเงื่อนไขคงที่ แต่ Agentic AI ในโครงงานนี้มีความสามารถด้าน **Autonomous Reasoning & Remediation** คือเมื่อตรวจพบความผิดปกติ เช่น มียารายการใหม่ที่แมปไม่ติด Agent จะตัดสินใจเรียก Tool ค้นหาบริบทและจับคู่รหัสยาเบื้องต้นให้ทันที ก่อนส่งข้อเสนอแนะและสรุปผลเข้า n8n ครับ"
